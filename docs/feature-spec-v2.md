# مشخصات قابلیت‌ها، معیارهای پذیرش، تست‌کیس‌ها و Definition of Done

نسخه: ۲.۰ | وضعیت: پیشنهادی برای اجرا | دامنه: چالش مانیتورینگ سرورها

## مدل سند
- هر Feature واحد مستقل تحویل است و شامل هدف، قرارداد پیاده‌سازی، Acceptance Criteria و Test Caseهای همان Feature می‌شود.
- هر Acceptance Criteria رفتار قابل پذیرش را تعریف می‌کنند؛ Test Case روش اثبات آن را.
- هر Definition of Done مستقل از فهرست Featureها و یک Quality Gate مشترک است: پاس‌شدن تست‌ها، الزامات غیرعملکردی، محدودیت‌ها، مستندات و آمادگی تحویل.
- هر Performance SLO و مقادیر ظرفیت در این نسخه «فرض و هدف پیشنهادی» هستند، نه نتیجه اندازه‌گیری. متن ماموریت دوم دریافت نشده است.
- پشتیبانی از نمودار یک‌ساله به معنی وجود تاریخچه تجمیعی است؛ حفظ داده خام یک‌ثانیه‌ای یک‌ساله الزام صریح نیست.

## فرض‌های قابل تأیید
- هفت سنسور درصدی در بازه ۰ تا ۱۰۰، یک نمونه به ازای هر دستگاه در هر ثانیه.
- داده‌ها با UTC ذخیره شوند؛ ارسال Timestampهای معتبر قدیمی طبق سیاست Late Arrival مجاز است.
- مرجع اولیه: ۱۰۰۰ دستگاه، ۱۰ کاربر Query هم‌زمان، حداکثر ۱۵۰۰ Bucket، p95 نمایش یک‌ساله < ۱۰۰۰ms.
- Retention پیشنهادی: Raw هفت روز، Minute چهل‌وپنج روز، Hour چهارصد روز. هر انتخاب در ADR بازنگری‌پذیر است.

# بخش B — Definition of Done 

**اصل پذیرش:** یک Feature تنها زمانی Done است که همه موارد مربوط در چک‌لیست زیر برآورده شوند. اگر موردی واقعاً نامرتبط است باید با دلیل در PR/Issue علامت N/A شود.

## کیفیت و تکمیل قابلیت
- [ ] همه Acceptance Criteria همان Feature با شواهد قابل ردگیری پاس شده‌اند.
- [ ] تمام Test Caseهای P0 آن Feature اجرا و Pass شده‌اند؛ برای تست‌های غیرخودکار، گزارش/اسکرین‌شات و دلیل ثبت شده است.
- [ ] هیچ نقص بحرانی P0/P1 باز مرتبط با Feature وجود ندارد.
- [ ] کد Review و Merge شده و تغییرات مخرب بررسی شده‌اند.

## آزمایش و خودکارسازی
- [ ] Unit، Integration و Smoke مربوط به تغییر در CI پاس می‌شوند.
- [ ] go test ./... و go vet ./... و بررسی Format بدون خطا هستند.
- [ ] تست‌های منفی، مرزی، تکرار درخواست و بازیابی متناسب با قابلیت اجرا شده‌اند.
- [ ] تست‌های End-to-End و Performance مرتبط در محیط مرجع اجرا و گزارش شده‌اند؛ Smoke/Load اسکریپت‌ها داخل مخزن هستند.

## الزامات غیرعملکردی (NFR)
- [ ] کارایی: برای نمودار یک‌ساله p95 End-to-End<1000ms با ۷ سنسور و ۱۰ کاربر هم‌زمان، فقط در سخت‌افزار و دیتاست مرجع تعریف‌شده.
- [ ] پایداری: پاسخ موفق تنها پس از durable ack؛ رفتار retry، dedup و crash مشخص و آزموده شده است.
- [ ] داده: correctness تجمیع، Gapها، Timestamp UTC، Retention و داده دیررس اثبات شده است.
- [ ] عملیات: Health Check، structured logs، metricهای request latency/error/ingestion lag/queue depth و timeoutهای معنادار موجودند.
